# Implementation plan tahap 5: API, Google login dan durable sync

## Kontrak dan cakupan

1. API Gin melalui use cases/core ports; ownership hanya dari cookie sesi terverifikasi. `GET /api/v1/exercises`, `GET /api/v1/workouts`, `GET /api/v1/workouts/:id`, `POST /api/v1/workout-mutations`; auth capabilities/current/start/callback/logout dan `DELETE /api/v1/account`. Reject unknown fields, ID nested asing, body media/pose, ukuran JSON berlebihan serta Origin/CSRF invalid. Backend menyajikan web build pada origin yang sama untuk localhost; development Expo dapat memakai origin/API URL eksplisit.
2. Mutation envelope: UUID account_id (harus cocok dengan identitas sesi, bukan sumber otorisasi), mutation_id/workout_id, base_revision nonnegative, operation upsert/delete, occurred_at, workout aggregate untuk upsert. Decimal beban memakai string kg maksimal tiga desimal atau NULL. Response immutable mencatat mutation/workout/revision/outcome dan aggregate final; 409 menyediakan revisi/versi server dan tidak melakukan partial writes. Canonical typed JSON SHA-256 membedakan retry identik dari reuse ID dengan payload berbeda.
3. Posisi set adalah urutan global sesi (gap di dalam setiap exercise diperbolehkan); mapper mempertahankan urutan ini saat membaca history. Provenance merged sources membawa timestamp/latihan/origin asli sebagai JSON typed, bukan timestamp buatan. Aggregate mempertahankan pause intervals/captured_at supaya history lintas perangkat tidak mengarang durasi/recovery. Tambah migration **003** dengan tes upgrade; jangan mengedit 001/002 yang sudah dipush. Frontend juga mempertahankan raw label/source: profil pilihan pengguna bukan klasifikasi otomatis; legacy yang tidak memiliki bukti label otomatis tetap unknown. Raw reps tetap independen dari final correction.
4. Sync repository PostgreSQL memakai transaction, per-owner/mutation advisory lock, parent revision lock, owner key-share lock dan outcome idempotensi `public.sync_mutations`. Retry respons hilang mengembalikan outcome yang sama; ID berbeda untuk revisi baru. Log outcome/workout atomic dan event occurred_at/correlation berasal dari envelope yang divalidasi. Deletion menggunakan tombstone; account deletion menghapus data/sesi/outcome serta identifiers logs dan menolak client identitas lama.
5. Google OIDC/OAuth authorization code dengan state browser binding, nonce, PKCE S256, expiry dan one-time consume. Core memakai provider/session ports; adapter Google memakai **go-oidc/v3 v3.21.0**, **x/oauth2 v0.37.0**, versi registry sudah diverifikasi. Validasi signature/issuer/audience/expiry + nonce sebelum issue session. Session dan CSRF token random; hanya SHA-256 tersimpan di DB. Cookie HttpOnly untuk session, Secure pada HTTPS, Lax; development HTTP hanya loopback. Tidak menyimpan access/ID token. Pending OAuth flow di memori dengan TTL; restart membatalkan flow pending, sesi login DB tetap berlaku.
6. Browser IndexedDB mempertahankan guest records; bindings akun terpisah agar login tidak otomatis mengimpor tamu. Outbox durable: mutasi yang telah dikirim immutable pada retry, coalesce hanya pekerjaan yang belum dikirim, acknowledge transactional dengan revision. Update terbaru setelah in-flight mutation mengantre mutasi baru. Auth expiry/network error mempertahankan hasil. User memilih local/server saat conflict; tidak ada overwrite diam-diam atau pengiriman hasil milik akun lama ke akun baru.
7. UI login/history/sync/import/delete di atas aggregate kamera/log yang sama. Import guest eksplisit, pilihan konflik, status pending/offline, logout dan delete tidak membuang guest results. Raw summary/history konsisten setelah correction. Model/SVG/video tetap lokal; outbox hanya JSON hasil, tanpa frame/pose/media.

## TDD dan validasi

- RED HTTP/use case: public catalogue, unauthorized owner history, strict request validation, cross-owner nested IDs, corrected summary dan auth rejection.
- RED identity/session: signed fixture JWKS token valid/invalid signature/audience/issuer/expiry/nonce, state cookie mismatch/replay/expiry, PKCE, hash-only session, CSRF/Origin, expiry/logout. Fixture issuer bukan bukti login Google nyata.
- RED PostgreSQL concurrency: dua request mutation yang sama menghasilkan outcome identik sekali, reuse beda payload ditolak, dua base revision hanya satu commit, revision conflict/log failure rollback, delete/tombstone/stale account session.
- RED browser/storage: guest import opt-in, outbox close/reopen/retry response loss, local edit saat request in flight, explicit conflict two clients, offline/reconnect, account deletion dan owner change. Gunakan DB nyata dan identitas fixture bertanda untuk E2E otomatis; OAuth produksi tetap adapter Google terverifikasi.
- GREEN/REFACTOR boundary core/HTTP/DB/browser, lalu frontend unit/type/build + Playwright; backend unit/integration/race/build/vet; migration/CLI dan localhost functional requests. Dokumentasi membedakan cryptographic fixture, real PostgreSQL, physical-device/live camera, dan Google end-to-end.

## Konfigurasi yang diperiksa

Draft environment tidak memiliki bindings OAuth, dan actual env names GOOGLE_CLIENT_ID/SECRET serta GYMBRO_GOOGLE_CLIENT_ID/SECRET semuanya belum terisi (nilai tidak dicetak). Siapkan kebutuhan client ID/secret dan callback lewat environment settings setelah implementasi independen siap diuji. Endpoint resmi yang dibutuhkan: accounts.google.com (discovery/authorization), oauth2.googleapis.com (token), www.googleapis.com (JWKS). Jangan meminta secret di chat atau membuat credential palsu untuk mengklaim login Google berhasil. Guest tetap dapat dipakai saat OAuth belum dikonfigurasi.

Live testing fisik/akurasi sesuai instruksi pengguna dilakukan setelah MVP runnable localhost. VPS dan auto-deployment menyusul ketika pengguna meminta deployment; tidak melakukan akses/publish/deploy sekarang.

File: `core/entity|repository|usecase`, `repository/{auth,sync,catalog}-repo`, `handler/api`, `pkg/googleauth`, `pkg/migration/sql/003_*`, `config`, `main.go`; frontend domain/mapper/storage/outbox/account UI dan e2e. Mark task hanya setelah semua perilaku yang disebutkan diuji; 5.4 tetap terbuka tanpa nilai OAuth dan login nyata.
